# 快速迭代：調整動作與情境時怎麼縮短每一輪

2026-10-08 起的做法。使用者反映：每次小調整都要完整重渲、等好幾小時（胸口挺 → 骨盆前傾 → 膝蓋彎，一次一個問題、每圈 1～2 小時）。以下規則適用於 `blender-animation-append`、`blender-creator`（02 動作、改服裝）、`blender-scenario-creator`。

## 0. 動作一律用 Mixamo 現成動畫原樣套上（2026-10-10 使用者規定，優先於下面各點）

**不再用 CMU 真人動作捕捉**（`library/mocap/`、`mocap_retarget.py` 只留作舊版成品的紀錄）。使用者說先前讓我依描述調整，「我的描述跟你實際做出來的效果有極大的落差」，所以改成以線上成熟動畫為底。

- **來源**：Mixamo（https://www.mixamo.com/）。
  - 使用者自己登入 Adobe 帳號；代理只在使用者開好的瀏覽器分頁裡找動畫、下載。**每一批下載先問使用者**（列出要下載哪些）。
  - 下載設定全用 Mixamo 預設、不調整：FBX Binary、**Without Skin**、30 fps、Keyframe Reduction none、In Place 關、Mirror 關。
  - 檔案放 `D:\render-work\mixamo\raw\<代號>.fbx`，同資料夾的 `manifest.json` 記每個檔的 Mixamo 名稱、描述、model_id、用在哪幾幕。用到新動畫就補一筆。
- **套到角色**：`scripts/mixamo_retarget.py`。
  - `read_fbx` 讀 FBX → `retarget(clip, Target(armature))` 原樣套到 VRoid 骨架（52 根骨頭，含手指）→ `Seg`／`Sequence` 接段 → `apply_pose` 擺到 Blender。
  - 套的時候**不鎖腳、不修手臂、不改姿勢**。骨盆位移只依腿長比例縮放。
- **代理只決定這幾件事**：用哪一支動畫、取第幾～幾秒（`Seg` 的 a、b）、從場景第幾秒開始（`at`）、走路循環幾次（`loops`）、站在哪裡、面向哪裡（`face`、`Sequence.place`）。段與段之間 **0.3 秒漸變**。
- **劇情不改**。Mixamo 沒有完全吻合的動作時（例：摸頭、餵食、乾杯、蹲著推地毯），挑最接近的當底，回報時寫明「用哪支代替什麼」。
- **套用後可以微調**（使用者 2026-10-10 同意）：接觸點對不上、穿模這類問題。但**不准破壞動作結構**：不重新設計動作、不改節奏、不把動作壓成固定秒數或步數。微調要寫進回報，說明改了哪根骨頭、幾度、為什麼。
- 門檻和現成動作衝突時，回報數字讓使用者決定，不要自行磨平。
- 由來：V12 ② 的走路為了塞進「3.2 秒、1.5 m、4 步」疊了九層加工，結果比純真人版更差（2026-10-08）；之後依描述調整的動作也和使用者想的落差很大（2026-10-10）。

## 0.5 兩關審看：先審骨骼，再審低畫質預覽（2026-10-10 使用者規定）

一支片有好幾幕時，照這兩關走。**第 1 關每一幕都確認了，才進第 2 關。**

| | 第 1 關：骨骼動作 | 第 2 關：低畫質預覽 |
| --- | --- | --- |
| 給使用者看什麼 | 3D 骨架播放器（不渲染，只有骨頭、道具方塊、蓬裙範圍） | 每一幕的快速預覽影片＋多角度檢查圖（§1、§2） |
| 看的重點 | 動作選得對不對、段落怎麼接、站位、面向、時間點 | 套上服裝後的樣子：穿模、接觸點、裙擺、臉有沒有被擋 |
| 怎麼產生 | `productions/<片>/scripts/mx_skeleton.py -- <幕>` → `D:\render-work\mixamo\review\s<幕>\skeleton.json` | §1 快速預覽（V12 是 `quick_tweak.py` 或各幕的 check 程式） |
| 審看網頁 | 樣板 `assets/skeleton_review/viewer.html`。每支片改 `<title>`、`ROUND`、`SCENES`；每幕的 `skeleton.json` 放 `s<幕>/` 一起發布 | 每一幕一張卡（影片、時間軸、數字、待決定） |
| 回饋存在哪 | 網頁的 db：collection `review`、doc `skel-<幕>` | 同一個 db：doc `prev-<幕>` |

- **兩關的審看網頁都要有**：每一幕一個回覆框（打字自動存）、**Ctrl+V 貼圖**、拖曳圖片、縮圖可放大或拿掉。使用者會在截圖上圈出疑點。
  - 發布時帶 `capabilities: {db: {}, assets: {}}`。圖片用 `assets.upload` 上傳，db 只存圖片 id、截圖當下的秒數與來源（貼上／畫面圈選）。
  - 第 1 關另有「在畫面上圈」：暫停後直接在 3D 畫面上畫紅圈，存成圖片加進回饋。
  - doc 形狀：`{scene, stage: "skeleton"|"preview", round, text, images: [{id, t, kind}], updatedAt}`。
- **主控端怎麼讀回饋**：`ArtifactData` 的 `list`（collection `review`）讀文字；圖片用 `Artifact` 的 `read`，`path` 填圖片 id，會存成本機檔，再用 `Read` 看。不用請使用者把回饋貼回對話。
- 下一輪更新**同一個網址**，`ROUND` 加 1。舊回饋留著，用 `round` 分辨。
- 第 1 關沒有網格，所以穿模、裙擺、接觸點這類問題留到第 2 關量。但能從骨架看出來的（例：腿踢出蓬裙範圍、兩人骨架重疊）要在第 1 關回報時先寫出來。

## 1. 兩種渲染：調整用「快速預覽」，定案才「完整品質」

| | 快速預覽（預設） | 完整品質 |
| --- | --- | --- |
| 什麼時候用 | 調整中、每一輪修正後給使用者看 | 使用者明確確認「這樣可以」之後 |
| 解析度 | ≤ 540p（動作預覽 360×540 照舊即可） | 情境 720p／1080p，照規格 |
| 引擎與取樣 | Workbench，或 EEVEE 低取樣 | 照規格 |
| 頭髮、裙擺物理 | **不跑**（固定姿勢或關閉擺動） | 照規格開啟 |
| 範圍 | **只渲染改到的片段**（例：只改走路就只渲走路那 2～3 秒＋前後 0.5 秒） | 整段 |
| 目標時間 | 一輪 10～15 分鐘內 | — |

- 數字檢查（穿模、腳底、滑步、轉速、速度突變）**每一輪照舊要跑**，快速預覽不代表放寬門檻。
- 主控端沒有明確說「做完整渲染」時，一律只交快速預覽。完整渲染前先問。

## 2. 交付「多角度檢查圖」，讓使用者一次看完

每一輪修正後，除了快速預覽短片，交一張拼圖：

- **橫排**：關鍵時間點（3～5 個，例如走路支撐期、擺盪期、併腳站定、接下一個動作的開頭；情境則是每個動作的中段與交接處）。
- **直排**：正面、側面、背面、3/4 四個角度。
- **改前、改後各一張**（同樣的時間點與角度），檔名標 `before`／`after`。
- 側面一定要有：骨盆前後傾、膝蓋彎曲、胸口挺、駝背這類問題只有側面看得出來。
- 角色穿**實際要用的服裝版**（西裝、蓬裙），不要只看便服。

## 3. 一次收齊所有問題再修

- 修一個問題時，**順便自己檢查同一套姿勢的常見問題**，量出數字寫進回報，讓使用者一次決定，不要等使用者一個一個發現：
  - 骨盆前後傾（骨盆骨頭相對垂直的角度；VRoid rest 本身就前傾 13.5°。舊的 CMU 版男性要套 `posture()`；Mixamo 原樣套用時不另外修，量出來回報）
  - 膝蓋彎曲（站定應接近打直，≤ 5°；走路支撐期中段接近打直）
  - 頭相對骨盆的前後位置（胸口挺 vs 駝背）
  - 手腕彎曲（握道具時往掌心折 > 30° 看起來像骨折）
  - 手指（張開或交叉、手勢的 spread 正負號）
  - 腳底（陷地、浮空、滑步）
- 回報時把**看到但沒修的**也列出來，標「待使用者決定」。

## 4. 瀏覽器即時預覽（姿勢微調）

- `scripts/export_web_preview.py` 把角色（服裝版）與動作匯出成 GLB，給主控端做的 three.js 預覽網頁用；使用者在網頁裡拖時間軸、轉視角，用滑桿即時微調（骨盆前傾、骨盆高度、膝蓋彎曲、上身前傾、手臂擺幅等），再把數值交回來。
- 收到網頁調好的數值時，**照數值套進動作庫**（以骨頭名稱與角度為準），再跑數字檢查與快速預覽確認，不要自行另外重新設計。
- 匯出規格：單一 GLB < 14 MB、骨頭保留 VRoid 原名、只匯出身體骨頭動畫、附 `bones.json`。
- 網頁樣板：`assets/web_preview/viewer.html`（three.js 0.160，滑桿：骨盆前後傾、腰椎、上身前傾、頭、骨盆高度、膝蓋彎曲、手臂擺幅、手臂外張；即時讀數：左右膝角、骨盆與上身前傾）。Artifact 平台不提供 `.glb`，要把 GLB 轉成 base64 存成 `<名稱>.b64.txt` 一起發布，網頁會載入後還原。新郎版：https://claude.ai/artifact/2nHvjEvmSYYsiLagHjWxUE

## 4.5 快修：小改由主控端直接跑，不派子代理（2026-10-09）

- 改時機、改幾個角度這類小改：**主控端自己改程式、自己跑快修**，不要派子代理。派子代理光讀文件就要 5～15 分鐘。
- 開場影片 V12 的快修工具：`productions/opening-v12/scripts/quick_tweak.py`。用法寫在檔頭。
  - 只算改到的秒數，前後各多算 0.5 秒。
  - 用 Workbench 灰模＋貼圖顏色出圖，不跑物理。
  - 只做骨頭層級的快速檢查：滑步、鞋底高度、轉速、速度突變。不算網格，所以不量穿模。
- 實測：② 走路 4.8 秒共 116 格，**整輪 4.5 分鐘**（建場景 33 秒＋每格 1.9 秒）。原本的做法每格約 9 秒。
- **穿模等網格檢查**等使用者說「可以」、要做完整品質之前，再用 `v2_quick_check`／`v2_phys_check` 跑一次。
- ⚠️ **慢的主因：擺姿勢時，每轉一根骨頭，Blender 都會把所有衣服的 Solidify／幾何節點修改器重算一次。**
  - 每次 `view_layer.update` 約 110 ms，一格要做好幾十次，所以每格 5.5 秒。
  - 把所有網格修改器的 `show_viewport` 關掉後，每次降到 13 ms，每格 0.35 秒。
  - 渲染走 `show_render`，畫面不受影響。
  - `pose_lib.mesh_eval(False)` 只關骨架變形，不夠。

## 5. 整支片批次審看（多幕）

2026-10-09 起的做法。使用者看整支片時，要求「每一幕的 3D 動畫先渲出來，我逐一看過後一次告訴你每一幕要修哪裡」。2026-10-10 起分成 §0.5 的兩關：workflow 的 `stage` 參數選第幾關。

- **由主控端呼叫 workflow `film-scene-review`**（`.claude/workflows/film-scene-review.js`）。子代理不能派子代理，所以批次一定從主控端發。
- `stage: 'skeleton'`（第 1 關）：每一幕的子代理只寫自己的 `scripts/mx_scene_<幕>.py`、跑 `mx_skeleton.py` 出 `skeleton.json`，不渲染。審看網頁用 `assets/skeleton_review/viewer.html`。
- `stage: 'preview'`（第 2 關，預設）：照下面的模式出快速預覽。**每一幕的骨骼都確認過才走這一關。**
- 兩關的網頁都要有回覆框＋Ctrl+V 貼圖（§0.5）。使用者也可以照舊在對話裡用「第 N 幕：…」回饋，兩邊都要讀。
- 每一幕一種模式：
  - `new`：這一幕還沒有 3D，新做。
  - `rerender`：用現行動作庫重渲，不改動作設計。
  - `fix`：照使用者回饋修正。
  - `existing`：沿用既有成品。
  - `full`：使用者確認後做完整品質。
- **會改同一支共用程式的幕要放同一個 `group`，依序跑**（例：`set_v2.py`、`shots_v2.py`）。其他幕各自並行。
  - 並行的幕不准改共用程式。非改不可時，把這一幕的邏輯放到自己的新檔。
- 交付格式（每一幕，路徑相對製作資料夾）：
  - 影片：`videos/preview-v2/sNN_<名稱>_quick.mp4`；完整品質用 `_full`。
  - 檢查圖：`pictures/preview-v2/v2_NN_check.jpg`。
  - 回報欄位：時間軸、數字檢查、這輪改了什麼、待使用者決定、動作來源（Mixamo 代號與取用秒數；舊版是真人動作捕捉的檔名與格號、動作庫代號）。
- 最後彙整成一個審看網頁（Claude Artifact）。每一幕一張卡：影片、時間軸、數字、待決定、回覆框＋貼圖。下一輪更新同一個網址。
- 使用者看完後，在網頁的回覆框寫（或在對話裡用「第 N 幕：…」逐條回饋）。主控端讀 db 的回饋、把圖片存成本機檔，回饋原話放進該幕的 `feedback`、圖片路徑放進 `feedbackImages`，模式設成 `fix`，再跑一輪。
- 使用者說某幕「可以」之後，那一幕才改成 `full`。沒確認的幕一律只交快速預覽。

## 6. 用量

- 每一輪結束就回報，不要自己連跑多輪完整渲染。
- 主控端給的輪數上限照守；到上限就停下來回報卡在哪。
