# AI 網格路線：照片 → ZEPETO 風 AI 頭 → 表情組 → 五官檢查與修正

> 狀態：**2026-10-14 起是正式產線**（一條龍 `/zepeto-character-face-generation-workflow` 的第三段，子代理 `zepeto-face-rigger`）。
> 2026-10-13～14 在 `D:/render-work/blender-work/zepeto-sculpt-trial/` 試做（新娘、攝影師），使用者看過後決定取代舊路線（模板當成品），
> 舊路線程式封存在 `D:/render-work/archive/zepeto-face-rig-old-route-20261014/`。
> 下面各節的「新娘」「攝影師」實測、對照圖都是試做資料夾裡的。

## 0. 為什麼有這條路線

| | 舊路線（2026-10-14 停用） | AI 網格路線（本文件，現行） |
| --- | --- | --- |
| 成品網格 | 通用模板頭（LucaDrech），包到 AI 頭外型上，顏色烘焙轉印過去 | **AI 生成的頭本身**（網格＋貼圖原封不動） |
| 模板的角色 | 成品 | 只當「籠子」：算出 52 個表情每一點怎麼動，再轉移到 AI 網格 |
| 外觀 | 會偏：AI 的 V 臉一部分是兩側髮絲畫出來的，頭髮底下的臉皮很寬 → 包子臉；眼線、陰影轉印位置對不上 | 原樣＝AI 原圖（V 臉、眼線、腮紅都在） |
| 代價 | — | AI 頭的眼睛、嘴巴是畫在貼圖上的：要自己切嘴縫、做口腔、做材質眼睛 |

研究依據（全文存在 references/）：
- [research-zepeto-face.md](research-zepeto-face.md)：ZEPETO 臉的比例特徵表、舊產線三顆頭差在哪、來源網址。重點是 V 字臉、杏仁眼、雙眼皮、上揚眼線、有唇峰的豐唇、小鼻有鼻樑、皮膚有光澤。ZEPETO 官方用「固定基底臉＋五官微調」，不是照照片重雕。
- [research-keep-ai-look.md](research-keep-ai-look.md)：保住 AI 外觀做表情的 9 種做法比較（含付費工具、要不要上傳）。採用「AI 網格當成品＋自寫表情轉移」；Blender 內建 Surface Deform 綁定失敗（模板有重疊頂點）。

## 0.1 痛點總覽（做這條路線一定會碰到的）

| 痛點 | 會怎樣 | 現在怎麼處理 |
| --- | --- | --- |
| Rodin 免費額度一天只有幾次 | 換描述重生、換人驗證都受限（2026-10-13 當天用完） | 生成一次就過的描述範本（第 1 節）；能不重生就不重生 |
| AI 頭是**單層殼**：頭髮、臉、耳朵、衣領是同一個網格，沒有頭皮、沒有口腔 | 其他端要的 `Hair`、`Ears` 要自己切；張嘴沒有開口；頭髮往後推會露出內側 | `pack_head.py` 切開；`transfer.py` 切嘴縫＋自建口腔袋；頭髮背面、內側偏亮貼圖畫成髮色 |
| 眼睛、嘴巴、眉毛、眼線**畫在貼圖上** | 閉眼時眼珠被壓扁、眼睛不會轉；嘴唇被拉成一片粉紅 | 材質眼珠＋材質眼皮；嘴縫照畫好的唇線切 |
| AI 的 V 臉是兩側**髮絲畫出來的** | 拿模板當成品（舊路線）就變包子臉 | 成品用 AI 網格；模板只當籠子（籠子仍要 V 臉，不然口腔袋從臉頰穿出） |
| 臉旁**細髮絲一半畫成膚色**、貼在臉前 | 顏色抓不到 → 留在臉上：被改成膚色、讓身體端把脖子量成 3 倍粗 | 用「往內射線 0.12 內打到另一層＝薄片」判斷，歸頭髮 |
| ZEPETO 畫風的五官偵測不穩 | 腮紅跟嘴連成一片、粗眼線被當眼睛、髮絲被當眼珠、閉嘴微笑的唇縫是 U 形 | 眼睛改用貼圖原色圖找眼珠＋眼白；唇縫用細線偵測；不準時 `face.json` 手動填 |
| 位移跟表情強度成正比 | 小表情看不出、張大嘴才露出凹凸 | 張嘴程度序列＋正中切片（`open_series.py`）一定要拍 |
| 長髮很厚、鐘形 | 推開會拆開、張成平板或披風 | `hair_fit.py` 壓縮做法；要拉遠拍側面才看得出披風（`shot_body_side.py`） |
| 長髮要先有身體才能調 | 身體照頭量尺寸做，頭換了身體要重出 | 用試接的身體跑頭髮（肩膀位置大致不變），再請身體端正式出廠 |
| 只看單張近照容易誤判（自己或外部 AI） | 背景被當破洞、正常的東西被當問題 | 第 4 節的驗證工具；4.4 外部 AI 注意事項 |
| 檢查和渲圖每次都重設表情值 | 存檔時留著的錯誤值（48 個表情存成 1）一直沒被發現 | 自動檢查加「打開檔案時非 0 的形態鍵」 |

## 0.5 一鍵產線（`scripts/run_face_rig.py`）

第 2～4 節的步驟串成一支程式，每張臉一個資料夾＋一個設定檔 `face.json`（一條龍是 `<OUT>/rig/`）：

```
python -u .claude/skills/zepeto-face-rig/scripts/run_face_rig.py --work <這張臉的資料夾> [--steps …] [--ai-blend …] [--body auto|none|<body.blend>]
```

| 步驟 | 做什麼 | 新娘實測 |
| --- | --- | --- |
| `post` | （face.json 有 `obj` 才跑）OBJ → 後處理成 .blend＋驗收圖；一條龍由後處理端做 | — |
| `eyes` | 眼睛自動偵測（`eyes_auto.py` 渲正面貼圖原色圖 → `eyes_find.py` 找眼珠、量開口）；有 `eyes_manual` 就用手動值；偵測結果不合理就停下來叫人填 | 4 秒 |
| `landmarks` | 五官（眼睛用上一步的值）；之後唇縫高度改用細線偵測（`eyes_find.find_seam`），寫回 landmarks.json | 4 秒 |
| `cage` | 籠子（`cage/`：V 臉預設開、不渲驗收圖） | 22 秒 |
| `transfer` | 表情轉移＋切嘴縫＋自建口腔袋 | 24 秒 |
| `shade` | 材質眼睛、眨眼、看方向、黑髮、亮澤 | 7 秒 |
| `check` | 自動檢查（數字）＋總表、嘴巴與眼睛近照、張嘴序列與切片 → `check/report.html` | 約 50 秒 |
| `rig` | 舊版 `head_rig.blend`（連同 `preview/`）改名封存 → 貼圖還原成 `shade` 的原版（`diffuse_blackhair_shade.png`）→ 整理成交接格式（`pack_head.py`，見「接身體」）→ 標準脖子接口環（`neck_ring.py`，見「頭身接縫」）→ 控制骨架（`face_rig.py`）→ **`head_rig.blend`**；骨架檢查（`rig_check.py`：每根控制骨頭拉到底，量形態鍵和材質數值、渲 15 格總表 `check/rig.png`，結果併進報告） | 15 秒 |
| `hairfit` | 長髮避開身體（`hair_fit.py`），改寫 `head_rig.blend`。face.json 的 `body`：`auto`（預設）＝用身體端的 `body_build.py` 照這顆頭試接一副身體（`D:/render-work/blender-work/zepeto-rig/<name>/body_try/prefit/`，`QA=none`）；也可給身體檔；`none` 不跑。再渲頭部分色三角度 `check/final_split_*.png`、骨架總表 `check/final.png`。**同一個檔只能跑一次**（會擋），要重跑從 `rig` 開始 | 約 70 秒（試接 45 秒） |
| `finish` | 貼圖打包進 `head_rig.blend` → 用成品再試接一次身體（`body_try/final/`，順便驗證身體端讀得了這顆頭）、拉遠拍側面 `preview/body_side.png` → `previews.py` 產預覽圖（`mat_front_ai／new`、`mat_34_ai／new` 同鏡頭燈光對照；52 個 ARKit 單一表情 `sheet_keys.png`）→ `sheet_combos.png`、`rig.png` → 耳朵近照 `check/ear.png`（`tools/ear_closeup.py`，左右耳各三張）、接身體的耳下到後頸近照 `check/nape.png`（`tools/nape_closeup.py`）→ `check/summary.json`（子代理讀這個回報）。`sheet_keys.png` 最後才產：身體端的頭清單看到它才算做完 | 約 110 秒 |

整條約 5 分鐘（新娘 280 秒）。改哪個值就從哪一步重跑（從某步起就把它和後面全部列上）：

| 改了 face.json 的 | 從哪步重跑 |
| --- | --- |
| `eyes_manual` | `eyes` |
| `mouth_zc`（唇縫中央高度，自動偵測不準時填） | `landmarks` |
| `mouth_cut`、`lip_smooth`、`lip_rz`、`brow_gain`、`tongue_len`、`corner_smooth` | `transfer` |
| `hair_rgb`、`iris_rgb`、`gloss` | `shade` |
| `body` | `rig` |

為什麼 `rig` 先還原貼圖：`hairfit` 會把耳垂以下改成膚色、存回 `diffuse_blackhair.png`；`pack_head.py` 照貼圖顏色分頭髮，讀到改過的圖，後頸分出來的範圍就變了（新娘重跑：脖子那層 64 點變 67 點，接口環跟著不同）。

為什麼貼圖要打包：成品原本讀外部 `diffuse_blackhair.png`，重跑 `shade` 會覆寫它；已經出廠的身體檔、封存的舊版跟著變（舊路線新娘 v4 的 `head_color.png` 出過這個事）。

`face.json` 第一次跑自動寫（`name`、`ai_blend`、`body`）；欄位與預設值寫在 `run_face_rig.py` 的 `FACE_DEFAULTS`（說明見 SKILL.md）。新娘試做的：

```json
{ "name": "bride", "ai_blend": "../ai/stylized_face_zepeto.blend", "eyes_manual": null,
  "hair_rgb": [0.075, 0.068, 0.072], "iris_rgb": [0.26, 0.15, 0.10], "body": "../body_try/out/body.blend" }
```

**自動檢查 `check.py`**（12 個代表表情，全部 0 才算過）：

| 項目 | 怎麼量 |
| --- | --- |
| 牙齒舌頭在唇前 | 牙齒、牙齦、舌頭的點比附近皮膚最前面還前面（吐舌頭時舌頭不算） |
| 口腔袋穿出（點） | 口腔袋深處的點跑到皮膚前面 |
| 口腔袋穿出（畫面） | 從正面、兩側斜面朝嘴巴射 90×64 條線：嘴裡的東西除了「嘴巴開口」那塊（最大一塊，或落在唇縫帶上的），其他 3 格以上的塊都算穿出 |
| 破洞 | 被臉圍住、卻什麼都沒打到的格子 |
| 看到皮背面 | 嘴巴附近（左右 1.5 個嘴寬、上下 0.12）、被臉圍住、打到 AI 皮背面的格子，3 格以上才算（1～2 格是擦邊的射線）；貼著嘴裡 3 格內的不算（唇內側）；唇緣從外面看到背面另外算 |
| 打開檔案時非 0 的形態鍵 | 檔案存的形態鍵值；沒接骨頭的表情存成 1 的話，一打開所有表情全開 |
| 嘴唇綁到模板內面 | 嘴唇表面綁到籠子「朝嘴裡」三角形的點數 |

除錯：`CHECK_DBG=<資料夾>` 會把每個表情、每個視角的射線結果存成 `.npy`（0 空、1 皮正面、2 皮背面、3 嘴內、4 穿出、5 破洞），用系統 Python 畫成圖（Blender 沒有 PIL）。

**檢查程式本身的驗證**：拿「沒修的模板當籠子」的壞版本（`bride/route_badcage/`，張嘴時口腔袋從臉頰穿出）跑一次，要抓到問題（實測 495）；新娘正常版要是 0。改了 `check.py` 就兩個都跑一次。

一鍵產線第一次跑時遇到的坑：

| 狀況 | 原因 | 修法 |
| --- | --- | --- |
| 所有表情嘴裡全是破洞、只剩牙齒 | 剛好 1 個點綁到面積 0 的三角形，重心座標是 NaN，抹順 40 次擴散到整張臉 | 退化三角形改用三角平均；形態鍵有 NaN 直接停下來報錯 |
| 某步沒產出檔案、下一步才報「找不到檔案」 | 程式有語法錯誤時 Blender 不印 Traceback、照常結束 | `run_face_rig.py` 看到 `…Error:` 開頭的行也算失敗 |
| 眼睛偵測抓到臉旁髮絲、眼尾小點 | 頭髮也是深色；眼珠連著眼線不夠實心 | 排除偏藍像素（頭髮）、實心門檻放寬但要夠大、挑對稱同高同大的一對 |
| 眼睛量得比手動大、程式眼白蓋過眼線 | 往左右走時連眼尾眼頭的眼線一起算 | 寬度 ×0.9 |
| 眼睛高度偏高、閉眼時下面露出一片眼白 | 眼珠連著上眼線，重心偏高 | 高度改用眼白上下範圍的中點 |
| 找不到眉毛 | 眼睛範圍太扁，往上翹的睫毛被當成眉毛起點 | 眼睛範圍上下放大 1.6 倍 |
| **骨架檔一打開臉扭成一團**（face.blend 也是） | 轉移時新增的形態鍵存成 1；檢查和渲圖每次都把所有值重設，所以一直沒發現 | 轉移時明確設 0、骨架步驟全部歸零；檢查加「打開檔案時非 0 的形態鍵」 |

### 換一張臉驗證（攝影師，2026-10-13）

Rodin 免費額度當天用完，改用攝影師**舊描述**生成的 AI 頭（男性、短髮、圓臉、圓眼、無腮紅、閉嘴微笑）跑一鍵產線，只讀正式資料夾的檔、不改。設定檔 `photographer/route/face.json`：`hair_rgb: null`（本來就是黑髮）、`corner_smooth: 0`、`brow_gain: 1.2`。

找到並修掉的通用問題（修完新娘仍是 0）：

| 狀況 | 原因 | 修法 |
| --- | --- | --- |
| 眼睛搜尋範圍切掉攝影師的眼睛下半 | 範圍只到頭頂往下 50% | 放寬到 60%；同時加「眼珠旁邊要有眼白」（眼睛 0.04～0.15，下巴陰影、深色髮絲是 0），不然新娘會配到下面一對深色塊 |
| 找不到眉毛 | 眉毛跟頭髮同色；眼睛上方零星的睫毛尖被當成眉毛起點 | 起點改用「最低一段夠密的深色點」（0.03 高度內 ≥ 6 點） |
| **嘴縫切在上唇上緣，一張嘴整片下唇連皮膚像板子掉下來** | 閉嘴微笑的唇縫是 U 形、中間比嘴角低 0.037；偵測到的「紅色帶中間」跟嘴角一樣高 | 唇縫高度改用細線偵測（`eyes_find.find_seam`：嘴巴中段每欄找比上下都暗的一列、取中位數）；`face.json` 可填 `mouth_zc` 手動 |
| 驚訝時嘴角外穿出一塊粉紅 | 口腔袋第 3 圈的寬度照口腔截面，比嘴縫末端寬，跑到嘴角沒切開那段皮膚正後方 | 第 3 圈左右寬度跟著嘴縫（`slitx`）；口腔袋深處也逐表情推到皮後 |
| 嘴角外側洋紅小塊（唇緣背面），閉嘴也有 | 唇緣第 2 圈往外張 0.006；攝影師嘴角附近下唇表面比唇縫高，唇緣穿到下唇前面 | 第 2 圈改成往另一片嘴唇收 0.004（`RIM_AWAY`）。試過沿皮膚法線往裡捲：上下兩片唇緣在縫裡交叉，退回 |
| 睜眼時上下露出 AI 的黑眼珠、閉眼蓋不滿 | 程式眼睛照 ZEPETO 杏仁眼（半高＝0.6 倍半寬）；攝影師是圓眼 | 半高＝max(0.6 倍半寬, 0.9 倍眼珠半徑) |
| 驚訝、難過眉毛變形太誇張 | 粗黑眉放大 1.6 倍太強 | 攝影師 `brow_gain: 1.2` |
| 嘴角折進去（懷疑嘴角抹平） | 實際不是抹平造成的（關掉還在）；元兇是上一列的唇緣 | 攝影師 `corner_smooth: 0` 保留，不影響結果 |

檢查程式也跟著補：唇緣從外面看到背面另外算（原本被當成嘴巴開口漏掉）、貼著開口 4 格內的碎塊算開口、貼著嘴裡的背面算唇內側。

結果：兩張臉自動檢查都是 0。攝影師還剩：閉眼時眼皮邊緣隱約看得到 AI 原本畫在圓眼外的粗眼線弧（舊描述的圓眼頭才有；新描述生成的杏仁眼不會）。

### 接身體（2026-10-14）

其他三端照舊頭的結構讀頭檔（`O["Head"]`、`ZEPETO_Skin`、`ZEPETO_Lips`、`Hair`、`Ears`、`Face_Rig` 的 `head` 骨頭）。
`rig` 步驟先跑 `pack_head.py` 整理成這個格式，**三端程式不用改**：

| 項目 | 做法 | 為什麼 |
| --- | --- | --- |
| `AI_Driven` → `Head` | 改名 | 身體、服裝、動畫都用這個名字找臉 |
| 頭髮切成 `Hair`（材質 `ZEPETO_Hair`） | 從頭頂沿網格長出像頭髮的顏色；下巴以下跟脖子中間隔空隙的細髮絲也算 | 身體端把脖子切口以下藏起來，頭髮跟臉同一網格的話長髮會被切掉；細髮絲留在臉上，身體端量脖子會量成 3.1 倍粗 |

### 2.4 自建口腔袋（`transfer.py` 1c 段）

- 唇縫的洞是一整圈（上唇切口＋下唇切口＋兩端嘴角），新娘 108 點。程式會印出「不是 2 條邊的點」，要是 0。
- 每一圈的位置：

| 圈 | 位置 | 材質 |
| --- | --- | --- |
| 1、2 | 唇緣：往後 0.008、0.02，第 2 圈上唇往上、下唇往下 0.006 | 皮膚材質，貼圖座標＝唇縫那一點（唇縫的顏色） |
| 3 | 貼在牙弓前面 0.012（牙弓＝牙齒＋牙齦每個 x 最前面的 y），截面 0.85 倍 | 口腔 |
| 4 | 牙弓後 0.03，截面全尺寸 | 口腔 |
| 5～8 | y＝-0.40、-0.29、舌根（舌頭最後面）、舌根後 0.03；截面 1.0、0.95、0.7、0.3 | 口腔；最後一圈補面收口 |

### 2.5 材質眼睛、眼皮、黑髮（`eyes_shader.py`）

```
blender -b <轉移後 .blend> -P eyes_shader.py -- <landmarks.json> <輸出 .blend>
```

| 部分 | 做法 | 控制值（材質節點） |
| --- | --- | --- |
| 黑髮 | 另存一張貼圖：像頭髮、偏藍的像素換成黑髮（保留明暗）；臉正面不碰；貼圖範圍很大的面（口腔袋、唇緣跨上下唇）不算臉正面 | — |
| 眼珠 | 眼睛範圍裡改畫程式眼珠（眼白＋深棕虹膜＋瞳孔＋反光）；**杏仁形、眼尾微翹**；用 `rest` 座標，黏在皮膚上跟著變形 | `LOOK_L_X`、`LOOK_L_Z`、`LOOK_R_X`、`LOOK_R_Z`（1＝虹膜移 0.35 個眼半寬） |
| 眼皮 | 閉眼時材質從上往下蓋一片膚色（取眼睛內側、下方的膚色），下緣一條「◡」閉眼線；用物件座標畫線 | `BLINK_Left`、`BLINK_Right`（網格的 eyeBlink 改名 `_geo` 停用） |
| 嘴角笑紋 | 張得越開，AI 畫在嘴角的深色短線越淡 | `JAW_OPEN` |

為什麼這樣做：AI 的眼珠畫死在貼圖上，平移貼圖座標會跳到別塊（貼圖是零碎拼貼）；橢圓眼睛跟 AI 的杏仁眼線對不上；用物件座標的話睜大眼時眼睛不跟著變大；用 `rest` 座標畫閉眼線會是鋸齒（逐三角面直線內插）。

| `nohair_view.py` | 藏起頭髮看 Head 哪裡沒皮（墊底皮塗黃） | 近照只看到「深色鋸齒」時，用這張才看得出是整片缺皮 |
| `neck_section.py` | 脖子截面數字：某高度切開幾段、閉不閉合、擬合橢圓；每層缺口邊界角度；墊底皮每層半徑 | `-- <高度> [<起> <終>]`；角度從脖子中心算（0＝正後）。缺口判斷要看「閉不閉合」，不要用固定角度範圍數開放邊（見 4.3） |
| `hair_check.py` | 頭髮體檢：碎塊、開口邊（真的破口）、插進身體的點**和面中心** | 開 `head_rig.blend` 或接好身體的 `body.blend`（有 Body 才查插進身體） |
| `probe_pick.py` | 身體端 `neck_probe.py` 的某一張近照，指定像素打射線：打到哪個物件、哪根骨頭的權重 | `-- ANGLE=180 PIX=x,y;x,y`（640×640 原圖座標）；查「頭髮上的膚色」是哪個部位 |
| `jaw_side.py` | 張嘴 0／0.5／1 的喉嚨側面、後頸斜後（頭髮藏起來） | `-- <前綴> side（或 back）`；看接口環附近的表情漸變會不會讓喉嚨折角、墊底皮會不會被戳破 |

## 4. 截圖五官 → 分析 → 修正（流程）

### 4.1 每一輪怎麼做

1. **拍**：`closeup.py` 拍表情 × 部位，正面加兩側斜面；張越大越容易壞的，用 `open_series.py` 拍程度序列。
2. **對照**：同機位拍 AI 原頭（`shot_ai.py`）。AI 原圖本來就有的（人中摺線、臉上細髮絲橫過眼角）不算問題。
3. **分類**：
   - 單色（`flat.py`）還在 → 形狀問題；單色消失 → 貼圖或材質問題。
   - 懷疑破洞 → `holetest.py`。
   - 不知道是哪個零件 → `dbg_parts.py`（嘴內）、`dbg_pocket.py`（口腔袋各圈）、`dbg_body_parts.py`（頭髮、臉、身體）塗色，或 `pick.py` 射線直接查。
4. **找原因**：用數字（`diag_bind.py` 這類）確認，再做**對照實驗**：一次只改一個變數，看問題會不會出現或消失。改了沒效果時，先確認改動真的作用在問題那幾個點上。
   - **接上身體之後**（脖子、頭髮、耳朵附近），照這個順序查：
     1. 看 `check/ear.png`、`check/nape.png`、`preview/body_side.png`（T 字姿勢），再用身體端 `neck_probe.py` 對 `body_try/final/out/body.blend` 拍一組（手臂放下的待機姿勢）。修之前先拍一組留著，修完同一支、同一組角度再拍，前後並排比。
     2. 看到**深色鋸齒**：`ear_closeup.py`／`nape_closeup.py` 加 `DBG` 分色——灰＝頭髮的邊、紅＝臉皮的邊；`nohair_view.py` 看是不是整片缺皮。
     3. 看到**頭髮上一塊膚色**：同一組鏡頭串 `hide.py`（`HIDE=Body`）再拍——頭髮完整＝身體從外面頂穿（不是破洞）；再用 `probe_pick.py` 打那個像素，看是哪根骨頭的部位；`hair_check.py` 看點和面中心有沒有插進身體、頭髮有沒有開口邊。
     4. 看到**細黑線**：`hair_check.py` 的碎塊列表（小塊的位置排成一條線＝AI 細髮絲碎片）。
     5. 量缺口：`neck_section.py`（截面閉不閉合、每層缺口邊界角度）。
5. **修**：改轉移或材質程式，從籠子重跑整條（約 4 分鐘），**用同一個機位重拍**比對。
6. **記**：原因、試過的失敗做法寫進程式註解和下面的坑表。

### 4.3 坑表（新娘試做實際遇到的）

| 看到的 | 真正原因 | 修法 |
| --- | --- | --- |
| 張嘴時上唇下緣鋸齒碎片 | 只有一條細縫分上下唇，其他點亂綁到對面 | 照 AI 唇線整片分上下唇 |
| 上排牙看不到 | AI 上唇比模板厚 | 上排牙齒、牙齦往下 0.025 |
| 嘴角小洞／尖角＋往臉頰的折線 | 切到嘴角；交界點隨機綁上唇或下唇 | 只切 80%；交界點取上下平均、越靠嘴角越平均 |
| 嘴裡深棕雜訊 | 看到 AI 皮背面 | 背面畫成口腔深紅 |

### 4.4 外部 AI 看圖分析的注意事項

使用者會把近照拿給其他 AI 分析、貼回來。實際上有兩條被提了三次，三次驗證都不存在：
- 「斜側嘴角破洞、露出灰色背景」：斜側近照的嘴角貼著臉的輪廓邊，背景就在旁邊。改用 `m34`／`m34R`（嘴角後面是臉頰）＋深藍背景後就不會誤判。
- 「牙弓一字型」：俯視是 U 形。

做法：**每一條都先用 4.1 的工具驗證再修**，驗證結果附圖回報；不要照建議直接改（例如「改用骨頭帶動張嘴」：張嘴形態鍵本來就是下顎剛體轉動，換骨頭效果一樣）。
