# 運鏡（Camera Motion）

運鏡＝**一鏡之內照片怎麼動**。寫在分鏡卡的「列-運鏡」。轉場（鏡與鏡之間）見 [[fx-transition]]。

## 共通規則

1. **分鏡寫法必須完整寫出參數**，不能只寫「慢推」。解析器（`storyboard-video-render/scripts/fx_notation.py`）只認下表的寫法，寫不完整會被擋下並列出可用寫法。
2. 全形括號 `（…）` 是給人看的說明，解析時整段忽略。例：`慢拉 115→100%（建立場景）`。
3. **預設是線性**（等速）。結尾加 `緩動` 改用 smoothstep。理由：線性運鏡在溶接交疊時兩鏡都在等速移動，看起來是連續的；緩動會在切點附近「停一下」。
4. 倍率 100% ＝照片剛好填滿版型的顯示區（A 版型是 1080 高的直式置中照片；H 版型是鋪滿 1920×1080）。
5. 方向箭頭 `→`／`←` 一律表示**照片內容在畫面上往哪邊移動**（不是鏡頭往哪邊轉）。
6. 圖示是分鏡卡上 15px 的 lucide 圖示，顏色用章節色。

### 品質鐵律（實作端，所有運鏡共用）

這三條是第 1 版被退件後修好的。少任何一條，投影時都看得出來：

| 規則 | 不做會怎樣 |
| --- | --- |
| **預先縮放**：照片從原檔一次縮到「本鏡最大倍率時的實際尺寸」（`kmax`），逐格只做 ≤1 的縮小 | 先縮小再放大，照片變軟 |
| **子像素定位**：AFFINE＋BICUBIC，座標保留小數；四周補 2px 邊緣像素＋BILINEAR 覆蓋遮罩 | 照片邊緣每隔幾格跳 1px，看起來「停停停跳」 |
| **靜止鏡對齊整數像素**（`snap`） | 沒有在動的照片被內插，整張微糊 |

驗證方法：拿一張純白圖跑運鏡，量每格邊緣位移的標準差（第 2 版從 0.36 降到 0.014）。

## 條目

### `zoom` 慢推／慢拉／微推

| 項目 | 內容 |
| --- | --- |
| 狀態 | 已實作（`render_storyboard.py` 的 `motion()`、`kmax()`） |
| 分鏡寫法 | `慢推 100→108%`、`慢拉 115→100%`、`微推 100→103%`；可加 `緩動` |
| 圖示 | 推：`zoom-in`；拉：`zoom-out` |
| JSON | `{"type":"zoom","from":1.0,"to":1.08}`（可加 `"ease":true`） |
| 適用版型 | A、H、B（B 時左右兩格同步縮放） |
| 演算法 | `k = lerp(from, to, p)`，p＝本鏡進度 0→1；以畫面中心為基準縮放。交疊型轉場期間 p 會略超出 0～1，倍率跟著外插，但**不低於 `min(from, to, 100%)`**（`fill_floor()`）—— 慢拉到 100% 的鏡過了切點不會縮到填不滿 |
| 慣用值 | 慢推 100→108%；一般慢拉 110→100%；**章節開場鏡**慢拉 115→100%；微推 100→103%（幾乎靜止但不死） |
| 使用時機 | 推＝靠近、情緒累積、特寫；拉＝帶出環境、收尾、章節開場建立場景 |

⚠️ 推拉幅度超過 115% 時，直式照片在 A 版型會明顯放大顆粒，原檔解析度要先確認（長邊 ≥ 顯示高 × 倍率 × 2）。

### `pan` 平移

| 項目 | 內容 |
| --- | --- |
| 狀態 | 已實作 |
| 分鏡寫法 | `平移 → 90px @105%`、`平移 ← 160px @110%`；可加 `緩動` |
| 圖示 | `move-horizontal` |
| JSON | `{"type":"pan","dir":"right","distance":90,"scale":1.05}` |
| 適用版型 | A、H |
| 演算法 | 照片固定放大到 `scale`，水平位移 `lerp(-distance/2, +distance/2, p)`；`dir:"left"` 時取負號 |
| 慣用值 | A 版型 90px @105%；H 版型 160px @110% |
| 使用時機 | 有方向感的畫面（走路、牽手往前、風景橫向延伸） |

⚠️ **`distance` 不能超過放大後多出來的寬度**：A 版型照片 720 寬 × 1.05 只多 36px，但 90px 位移能用，是因為 A 版型兩側有模糊底，照片邊緣露出來看起來仍自然；H 版型滿版就**不能露邊**，條件是 `distance ≤ 1920 × (scale − 1)`（110% 時上限 192px）。
⚠️ **接溶接／推移時要再留餘裕**：交疊期間位移會照同一速度外插（平移沒有像倍率那樣的下限），H 版型實際走的距離是 `distance × (1 + 前後交疊半長合計 ÷ 鏡長)`。例：5 秒鏡、前後各接溶接 0.8s → ×1.16，110% 時 `distance` 上限約 165px（範例的 160px 剛好安全）。
⚠️ 垂直平移（↑↓）目前**未實作**。

### `split-counter` 分割畫面一推一拉

| 項目 | 內容 |
| --- | --- |
| 狀態 | 已實作 |
| 分鏡寫法 | `分割一推一拉 左100→106% 右106→100%` |
| 圖示 | `zoom-in` |
| JSON | `{"type":"split-counter","left":[1.0,1.06],"right":[1.06,1.0]}` |

| 使用時機 | 新郎／新娘單人照對照；兩張照片的情緒互相呼應 |

### `split-fly` 分割上下飛入

| 項目 | 內容 |
| --- | --- |
| 狀態 | 已實作（2026-10-14；`render_storyboard.py` 的 `split_fly()`、`ease_out_cubic()`、`kmax()`；解析在 `fx_notation.py` 的 `MOTIONS`／`MOTION_LAYOUTS`；長度限制在 `build_storyboard.py` 的 `validate()`）。提案：`.claude/docs/fx-lab/motion-split-fly.md`；使用者直接拍板、略過預覽，實際效果在第 3 版影片預覽時確認，不滿意再調參數。驗證：第 3 版 S2-04 逐格抽格（1:12.55～1:13.6 連續格、1:15.78～1:16.08 推移出場），確認硬切後首格全底色、左格先由上飛入、右格晚 0.2s 由下飛入、未進場處露底色、無回彈；回歸：範例 `our-moments.storyboard.json` 12 個時間點逐像素相同 |
| 分鏡寫法 | `分割上下飛入 左↓ 右↑ 0.7s 延遲0.2s 微推100→103%` |
| 圖示 | `arrow-down-up` |
| JSON | `{"type":"split-fly","left":"down","right":"up","duration":0.7,"delay":0.2,"zoom":[1.0,1.03]}` |
| 適用版型 | B |
| 參數 | `left`／`right`：該格**內容移動方向**（同共通規則 5）。`↓`＝`"down"`＝從畫面上方飛入、往下就位；`↑`＝`"up"`＝從下方飛入、往上就位。`duration`：每格飛入秒數。`delay`：右格比左格晚幾秒起飛。`zoom`：全鏡的推拉起訖倍率（寫 `微推100→100%` 等於飛入後靜止） |
| 慣用值 | `左↓ 右↑ 0.7s 延遲0.2s 微推100→103%`（S2-04：新郎由上往下、新娘由下往上） |
| 使用時機 | 新郎／新娘單人照對照、「兩個人從各自的世界走到一起」的意象；章內偶爾用一次當亮點，不要連續兩鏡都用 |

**演算法**（逐格；t＝絕對時間、s＝本鏡起點＝前一鏡的切點）：

1. **每格是一個整體**：格子＝「模糊底＋直式原圖」合成好的半邊（寬 959、高 1080，同既有 B 版型），飛的是整格，不是只飛照片。格子只在自己那一欄內出現（左欄 x 0–958、右欄 x 961–1919），超出畫面上下緣的部分裁掉。
2. **推拉**：格內照片倍率 `k = fill_floor(lerp(zoom[0], zoom[1], p), *zoom)`，p＝本鏡進度 0→1，**線性、全鏡都在跑**（飛入途中也在推），以格子中心為基準，同 `zoom`。這樣飛入結束時沒有「停一下再開始推」的頓點。`kmax = max(zoom)`。
3. **飛入進度**：左格 `u_L = (t − s) / duration`，右格 `u_R = (t − s − delay) / duration`，各自夾在 0～1。
4. **緩動**：`e(u) = 1 − (1 − u)³`（easeOutCubic：起飛快、落地柔，不回彈）。
5. **垂直位移**（px，正值＝往下）：`"down"` 時 `dy = −H × (1 − e(u))`（從 −1080 走到 0）；`"up"` 時 `dy = +H × (1 − e(u))`（從 +1080 走到 0）。H＝1080，所以起飛時整格完全在畫面外。
6. **合成**：先畫一張全畫面 `BACKDROP`（`規格-底色`，本片 `#1E2A33`），再把每格依 dy 貼進自己那一欄。位移用子像素：整格當一張圖，以 `place_sub(canvas, cell, x0, dy, 1.0, clip=該欄)` 貼上（AFFINE＋BICUBIC、四周補 2px＋BILINEAR 遮罩，符合品質鐵律第 2 條），dy 保留小數。`u ≥ 1` 後 dy＝0，直接整數貼上。
7. **未進場的區域**：格子還沒蓋到的地方露出 `BACKDROP`（與 `split-late` 淡入前的底色、B 版型中縫同色），**不是黑、也不是上一鏡**。中縫 2px 全程是底色。

**與轉場時間窗的互動**（飛入的時鐘以**切點 s** 起算，不以交疊窗起點起算）：

| 前一鏡接進來的轉場 | 畫面上會發生什麼 | 建議 |
| --- | --- | --- |
| `硬切` | 切點那格就是全底色，兩格接著飛入 | ✅ 首選：飛入動作最乾淨 |
| `溶接 d` | 切點前 d/2：本鏡還沒起飛（u＜0），畫面是全底色 → 上一鏡溶到底色；切點後 d/2：兩格一邊飛入、一邊溶接完成 | ✅ 可用，`d ≤ 0.6s`；溶接越長，前一鏡的殘影越會壓在飛入的格子上 |
| `推移 → / ←` | 整個畫面水平推入、格子同時垂直飛入，變成斜向亂動 | ❌ 不要搭配；要推移就改用其他 B 運鏡 |
| `閃白` | 切點後 `post` 秒內白光退去，格子在白光裡起飛 | ⚠️ 可用但飛入前段被白光蓋掉；`post ≤ 0.2s` |
| `黑場 a+b` | 從黑淡入的同時起飛，前段飛入看不見 | ⚠️ 不建議；章節開場鏡請用 A／H 版型的慢拉 |

本鏡**接出去**的轉場（寫在本鏡的轉場欄）照常運作：飛入早已結束，交疊期間 p＞1，推拉照 `zoom` 規則外插（不低於 `fill_floor` 下限）。

**長度限制**（實作時加進 `build_storyboard.py` 的 `validate()`）：`delay + duration` 不能超過本鏡長度的一半（預設 0.9s → 本鏡至少 1.8s；建議 ≥ 3s，讓兩人並排至少停 2 秒）。

**預設值的理由**：

- **0.7s**：0.5s 以下在投影上像「閃一下」，長輩來不及看清是誰飛進來；1s 以上變成拖沓的滑入。0.7s 搭配 easeOutCubic，前 0.2 秒就走完約 6 成距離（俐落），後半段慢慢落定（溫柔）。
- **延遲 0.2s**：比 0.15s 更看得出「先新郎、後新娘」的一問一答；超過 0.25s 會像右格出錯慢了。和 `split-late` 的 0.2s 一致，整片節奏統一。
- **easeOutCubic、不回彈**：回彈會讓格子超出就位點再彈回，超出的那一下格子另一端會露出一條底色縫，在大螢幕上很明顯；而且回彈的俏皮感不合婚紗片。
- **微推 100→103%**：飛入後畫面不死，但幅度小到不會跟飛入搶注意力。

**已知坑**：

- ⚠️ **第一格位移很大**：easeOutCubic 起飛速度是平均速度的 3 倍。30fps 時左格第一格就移約 147px，沒有動態模糊會有一點「跳出來」的感覺。若預覽覺得跳，先把 `duration` 拉到 0.8s，不要改成線性（線性落地會「撞」到定位）。
- ⚠️ **不要套品質鐵律第 3 條的 `snap`**：飛入途中必須用小數座標，否則最後 0.2 秒的慢速段會一格一格跳 1px。只有 `u ≥ 1` 且 `zoom` 起訖相同（等於靜止）時才對齊整數像素。
- ⚠️ **臉的位置**：新郎從上方進來，畫面先看到的是照片**下半身**；新娘從下方進來，先看到**頭頂**。照片人物偏上緣構圖時，方向可以對調（`左↑ 右↓`）。
- ⚠️ 長輩觀看：一章最多用 1～2 次。大面積垂直快速移動在投影上比水平移動更容易讓人覺得晃。
- ⚠️ 底色要夠暗：未進場區域會露出 `BACKDROP` 約 0.5～0.9 秒，若底色改成亮色，飛入前會先閃一片亮色塊。

## 新增運鏡時

1. 先走 `fx-lab` 子代理做預覽、由使用者拍板，條目以「已定案・待實作」寫進本檔。
2. 實作端（`storyboard-video-renderer`）遇到分鏡用了「待實作」的運鏡時，三處一起改：`fx_notation.py` 的 `MOTIONS`、`render_storyboard.py` 的 `kmax()`／`motion()`（必要時 `render_shot()`），以及 `MOTION_LAYOUTS`。
3. 改完把狀態改成「已實作」，並記下驗證方式。⛔ 不要只改文件或只改程式 —— 兩邊不一致時，分鏡稿會畫出解析器不認得的寫法。
