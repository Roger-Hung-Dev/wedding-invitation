# 新版 ZEPETO 身體（手模板、腳 v2）對動畫端的影響：研究報告

> 2026-10-14，身體端（zepeto-body）轉使用者的請求。**只研究，沒有重套任何鏡頭。**
> 新身體還沒出廠，開場片 B 照用新娘 v3。換版前會先問導演和使用者。
> 身體端的改動見 `zepeto-body-generation-workflow/references/zepeto-body-v2.md` 2.4、2.5：
> - 腳長 13.6 → 23.2 cm。
> - 腳踝關節高 2.3 → 8.3 cm。
> - 腳趾關節往前約 6 cm。
> - 手改成固定模板，手的骨架沒變。

## 先講結論

| # | 項目 | 結論 | 要動程式嗎 | 主要哪一端做 |
| --- | --- | --- | --- | --- |
| 1 | 新手勢（OK、雙手合十） | **OK 手勢**：在共用手勢庫加一筆就好，現有寫法夠用。**雙手合十**：不是單手手勢。要兩隻手臂一起用 IK 對到一個「共用掌心點」，需要新寫一個小工具 | OK：加一筆資料。合十：新增約 40 行 | 動畫端加；身體端驗證比不比得出來 |
| 2 | 特殊姿勢的接觸與穿插 | 我們已經在走業界標準的三步：原樣套用 → 只在接觸點用 IK → 逐格量穿插。缺的是「膝蓋著地」「兩腿互相穿插」兩種量測 | 補兩項量測 | 動畫端 |
| 3 | 換新身體後重套已定案的鏡頭 | **大部分會自動對**。原因有三：髖的高度沒變，所以整個人的移動路線不變；鞋底貼地點從網格自動抓；腳的轉動是照「站直時」的差量套上去的。要對照的是落地格號、骨盆路線、手和道具的距離。建議寫一支對照程式當驗收 | 新增對照程式 | 動畫端；換版時每鏡重跑 |
| 4 | 貼地鎖腳 | 程式**會**照新骨頭和新網格自動算。但有一個風險：腳變長、腳踝變高後，「釘住腳踝」在腳跟抬起、前腳掌還踩著那幾格，會讓前腳掌往後滑 | 建議改成「釘住踩地的那個點」 | 動畫端 |
| 5 | 長髮被上臂頂出來 | 主力推薦**修正形態鍵**：頭髮預先雕好一個讓開的版本，強度由上臂轉的角度自動控制。結果穩定、每次都一樣、成本低。要甩動的鏡頭，再另外加頭髮物理模擬 | 新增一個形態鍵＋一個驅動器 | 建議頭端做一次（頭身接好時），動畫端每鏡量、必要時調強度。**還沒定，等使用者決定** |
| 6 | 不套 Mixamo、自己做動作 | **最划算的是「Mixamo 當底、只改局部」（我們現在的做法）**。Mixamo 沒有的劇情動作，可以加「手機拍真人 → 抽動作 → 只取手臂那一段疊上去」當補充。文字生成、其他動作庫幫助不大 | 現在不用。要試影片抽動作，先做 1 天小實驗 | 動畫端；規則要不要改由使用者決定 |

## 1. 新的具名手勢

### 真人參考

| 關節 | 正常可彎範圍（醫學量測） |
| --- | --- |
| 四指：根部 MCP／第二節 PIP／指尖 DIP | 80–90°／100–115°／60–90° |
| 拇指：根部 CMC／MCP／IP | 45–50°／50–60°／80–90° |
| 指尖捏取時實測 | 食指 MCP 約 57°、PIP 約 51°；拇指 MCP 約 19°、IP 約 43° |

- 來源：https://pmc.ncbi.nlm.nih.gov/articles/PMC4372184/table/tbl3 、https://www.physiotutors.com/wiki/wrist-hand-active-range-of-motion/ 、https://pmc.ncbi.nlm.nih.gov/articles/PMC3226898
- OK 手勢、合十**沒有找到專門的量測**。下面的角度是從捏取數據推出來的「起始值」，最後要用近照和穿插數字調定。

| 手勢 | 起始值（推估） | 要點 |
| --- | --- | --- |
| OK | 食指 (50, 60, 30)；拇指 (15, 20, 35)；中指 (8, 10, 5)、無名指 (14, 16, 8)、小指 (20, 22, 10)；四指微張 | 拇指指腹碰食指指腹（不是指甲碰指甲），中間圍出一個圓洞 |
| 合十 | 四指 (5, 3, 2) 併攏；拇指 (0, 5, 5) 貼著食指側邊 | 兩隻手腕往後扳 60–90°，兩個掌心面對面 |

### 加進共用手勢庫的寫法

共用手勢庫是 `blender-motion-library/scripts/mixamo_retarget.py` 的 `GESTURE`。

- **每筆的格式**：`curl`（每根手指 3 節的彎度）、`spread`（手指張開）、`thumb_to`（拇指尖要壓到哪一節）。
- **OK 手勢**：照這個格式加一筆 `"ok"`，`thumb_to="Index3"`（拇指尖壓到食指第 3 節）。拇指會用 IK 自動對過去，接觸距離照骨架屬性 `thumb_contact`。
- **新手模板已經改了接觸距離**：身體端改成 17.5 mm（`THC`），比讚的彎度改成 ×0.8。這兩個值要寫進新身體骨架的 `thumb_contact` 和 `gesture_overrides`。這兩個欄位已經有了，「每副身體自己帶一組微調」的機制本來就支援。
- **雙手合十**：只改手指不夠，兩隻手臂也要動。做法是新增 `zanim_hand.palms_together(tgt, R, hips, center, normal, gap)`：
  1. 在胸前放一個「共用掌心點」和一個掌心朝向。
  2. 左手照這個點和朝向，用現有的 `put_hand_pole` 對上去；右手用鏡射的朝向。
  3. 兩個掌心各往外退 `gap`（皮膚厚度的一半，約 1–2 mm）。
  4. 手指套 `"pray"` 手勢。
  - 業界常見做法相同：一手為主、另一手鏡射，兩手的 IK 都對到同一個中間點。Blender 姿勢庫也內建左右鏡射（Apply Pose Flipped）。
  - 來源：https://docs.blender.org/manual/en/latest/animation/armatures/posing/editing/pose_library.html 、https://blog.animschool.edu/tag/animating-hands/

### 怎麼驗證

| 檢查 | 標準 |
| --- | --- |
| 身體端 `hand_probe.py -- GEST=lib` 近照（新手勢會自動列進去） | 目視：OK 看得到圓洞；合十兩掌貼平、沒有縫 |
| 身體端 `body_checks` 量法 v2 | 不同部位穿插 ≤ 1 mm；關節內側擠壓 ≤ 4.64 mm |
| 合十另外量「左手皮膚進右手」 | 兩掌最深 ≤ 1 mm；掌心中央的空隙 ≤ 3 mm（看起來是貼著的） |

### 對身體端、服裝端的影響

- **身體端**：驗證新手勢比不比得出來。如果新手模板需要不同的彎度，寫進那副身體的 `gesture_overrides`，不要改共用值。
- **服裝端**：有袖口的衣服，合十時手腕往後扳 60–90°，袖口可能被扳進手腕。要加一個袖口姿勢的檢查。

## 2. 特殊姿勢（交叉站、跪坐、蹲、和道具對位）

### 業界做法

- 重定向工具本身不處理接觸。例如 RetargetKit 的文件明講它「不解 IK、不鎖腳、不修腿長不同造成的滑步」。標準流程是先套用動作，再另外修接觸點。
  - 來源：https://superhivemarket.com/products/retargetkit/docs
- **IK**：
  - 用 Chain Length 限制只動 2 節骨頭（大腿＋小腿，或上臂＋前臂）。
  - 用 Pole Target 指定膝蓋、手肘朝哪個方向。
  - 來源：https://docs.blender.org/manual/en/latest/animation/constraints/tracking/ik_solver.html
- **穿插量測**：用 `mathutils.bvhtree`（一種加速空間查詢的結構），每格量一次：
  - `overlap()` 列出兩個網格互相穿進去的面。
  - `find_nearest()` 量某一點到表面的距離。
  - 來源：https://docs.blender.org/api/4.2/mathutils.bvhtree.html

### 我們現在的做法，和要補的

我們已經在走同樣的三步：原樣套用 → 只在接觸點用 IK → 逐格量。

| 已經有的 | 在哪 |
| --- | --- |
| 手對道具（IK＋膝蓋、手肘方向） | `zanim_hand.put_hand_pole`、`hand_quat`；`zanim_fix.leg_ik` |
| 手指碰到就停 | `finger_pose` 的 `thumb_to`、接觸距離 |
| 皮膚和衣服逐格量 | `gown_check.py`（從裡面往外打射線判斷在不在裡面） |

| 要補的 | 為什麼 | 做法 |
| --- | --- | --- |
| 膝蓋著地點（跪坐） | 現在 `foot_lock` 只找鞋底，跪坐時膝蓋會陷進地板或浮起來 | 鞋底取點的做法照抄一份給膝蓋。跪坐那段膝蓋最低點貼地（離地 0–2 mm） |
| 兩腿互相穿插（交叉站、蹲） | 現在只量「人和禮服」「人和人」，沒量自己的左腿進右腿 | 用 BVH `overlap()` 量左腿網格對右腿網格。標準：0 個面穿插 |
| 跪坐、蹲的膝蓋方向 | 深蹲時 IK 的膝蓋會往內倒 | `leg_ik` 的膝蓋方向改成「沿腳尖方向往外 10–15°」 |

### 對身體端、服裝端的影響

- **身體端**：跪坐、深蹲時大腿和小腿貼在一起，膝蓋內側會被壓扁。這是身體權重的事，建議身體端把「跪坐」加進出廠檢查的姿勢。
- **服裝端**：褲子和裙子在跪坐時會被大腿和小腿夾住，要用同一個姿勢檢查。

## 3. 換成新身體時，已定案的鏡頭怎麼重套

### 我們的重套程式會怎麼反應（看過程式）

`mixamo_retarget.retarget()` 做三件事：

1. **骨頭轉動**：每根骨頭照「Mixamo 這一格相對站直時轉了多少」，套到我們骨架站直時的方向上。
   - 腳（Foot、ToeBase）**不做方向對齊**，只套轉動的差量。
   - 新腳站直時是平貼地面的，所以 Mixamo 腳平的時候，新腳也平。腳變長、腳趾關節前移都不會讓腳尖方向跑掉。
2. **骨盆移動**：乘上一個縮放比例 `s` ＝ 我們的髖高 ÷ Mixamo 的腿長。
   - 身體端說髖和膝蓋的高度不變，所以 **`s` 不變，整個人走的路線和原本定案的一模一樣**。
3. **貼地**：
   - `ground()` 和 `foot_lock()` 用的鞋底點，是從網格自動抓的（站直時離地 ≤ 1.2 cm、屬於 Foot 或 ToeBase 的點）。
   - 換了腳會自動抓新的鞋底，不用改參數。

### 會不一樣的地方（要對照的）

| 變化 | 會怎樣 | 嚴不嚴重 |
| --- | --- | --- |
| 腳踝高 6 cm、膝蓋不動 → 小腿短 6 cm | 膝蓋彎的時候，腳離骨盆近一點。蹲和坐的姿勢腳會稍微往後縮 | 走路、站著看不出來；坐和蹲要看 |
| 腳長 23 cm、腳趾關節前移 | 腳跟抬起、腳尖往下踩時（起步、踮腳），腳尖會比以前多插進地 1–2 cm。程式會把腳踝抬回來，骨盆就跟著上下多動一點 | 中：B0～B6 有轉身、起步的鏡頭要看 |
| 腳變長 | 兩人站得近時（扶背、牽手），腳尖可能互相碰到，或踩進禮服裙襬 | 中：B5、B6 要重跑 `gown_check` |
| 手換成模板 | 握道具（蛋糕、手機、鑰匙）時，手指接觸距離改了，握點可能差幾 mm | 低：手指碰到就停的程式會自動修 |

### 業界做法

- **Unreal IK Retargeter**：
  - 骨盆的水平和垂直移動，依兩副骨架的骨盆高度比例縮放。
  - 每條腿有自己的 IK 目標，負責貼地。
  - 兩副骨架站直時的姿勢要先一致，不然偏差會出現在每一格。
  - 來源：https://dev.epicgames.com/documentation/unreal-engine/retargeting-operation-stack-in-unreal-engine?lang=en-US 、https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/IKRetargetPelvisMotionOpSettings.html
- **Rokoko**：遇到腳穿地或臀部不動時，建議關掉自動縮放，改用骨盆高度。
  - 來源：https://support.rokoko.com/hc/en-us/articles/4410463481489-Retarget-an-animation-in-Blender
- 我們本來就照骨盆高度縮放，和業界做法一致。

### 怎麼確認重套後和原本定案的一致

建議新增一支對照程式 `retarget_diff.py`。對同一鏡，用舊身體和新身體各跑一次 `build`，每格比對：

| 指標 | 標準 | 業界依據 |
| --- | --- | --- |
| 骨盆位置差 | ≤ 1 cm（貼地修正造成的上下差 ≤ 2 cm） | 比對根骨路線 |
| 每隻腳落地、離地的格號 | 差 ≤ 1 格 | 比對接觸時刻 |
| 髖、膝、踝、肩、肘的角度曲線 | 相關係數 > 0.95 | 比對關節角度曲線 |
| 手到道具的距離（拿、咬、牽手） | 差 ≤ 5 mm | 我們自己的接觸規則 |
| 兩人最近距離、人進禮服 | 重跑 `gown_check` 照舊過關 | — |

- 對照程式只算數字，不用渲染，一鏡約 1 分鐘。
- 數字過了，再照第 7.5 步渲小片段（固定機位全身＋腳部特寫）自己看過，才交確認頁。

### 對身體端、服裝端的影響

- **服裝端**：鞋子、褲腳一定要重做，身體端已經寫了。新娘禮服的裙長要確認：腳長變長，腳尖可能從裙襬前面露出來。
- **身體端**：出廠時 `RELEASE.json` 要寫明「骨架有變動」，讓動畫端知道要重套，不只是換皮。

## 4. 貼地鎖腳

### 我們的鎖腳程式是不是自動算？——是

`zanim_fix.foot_lock()` 和 `ground()` 的作法：

- 鞋底點從網格自動抓（`zanim_lib.sole_points`），跟著新腳的形狀走。
- 判斷「著地」用兩個條件：鞋底最低點離地 ≤ 1 cm，而且腳踝水平速度 ≤ 0.30 m/s，連續 4 格以上。
- 著地那段把**腳踝**的水平位置釘住，前後 3 格漸入漸出。
- 每一格只要鞋底低於地面，就用 IK 把腳抬回來。

### 業界做法和門檻

| 來源 | 做法 | 門檻 |
| --- | --- | --- |
| Kovar 等人 2002（經典鎖腳演算法） | 每段著地挑一個固定點 → 解腳的方向 → 骨盆移到腿搆得到的地方 → 修正量平滑帶進前後格 | — |
| Unreal Foot Placement | **腳跟**是主要固定點、**前腳掌**是次要固定點；固定和放開用兩個不同的速度門檻，中間那段就是腳往前翻的過程 | 沒給數字（節點還在實驗階段） |
| PhysCap 論文 | 前腳掌和腳跟分開判斷 | 速度 < 5 cm/s，而且高度 < 平均腳高 + 5 cm |
| UnderPressure 論文 | 只看速度或只看高度，準確率都只有約 57% | 兩個條件要一起用，再加「最少維持幾格」 |

- 來源：https://research.cs.wisc.edu/graphics/Gallery/FootskateSolver/footskate.html 、https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/FootPlacementPlantSettings 、https://arxiv.org/pdf/2008.08880 、https://arxiv.org/pdf/2208.04598

### 新腳的風險

- **問題**：我們釘的是**腳踝**。腳跟抬起、前腳掌還踩著地的那幾格，真人的腳踝會繞著前腳掌往前、往上轉。
  - 舊腳的腳踝只高 2.3 cm，這段轉動很小，看不出來。
  - 新腳的腳踝高 8.3 cm、離前腳掌更遠，轉動的弧比較大。
- **會怎樣**：這時腳踝的速度可能還低於 0.30 m/s，程式把腳踝釘住，前腳掌就會往後滑。估計 1–3 cm，起步、轉身時最明顯。

### 建議

1. **著地時改成釘住「踩在地上的那個點」**：腳跟、前腳掌、腳尖各算一個點，誰最低就釘誰，再用 IK 反推腳踝位置。
   - 只要改 `foot_lock` 裡算 `xy` 的那一段。
   - 鞋底點用「在腳跟到腳趾關節之間的哪個位置」分成三組。
2. **門檻照腳長換算**：高度門檻 1 cm 對 23 cm 的腳偏嚴，改成腳長的 5%（約 1.2 cm）。速度門檻維持 0.30 m/s。
3. **檢查門檻**（第 7.5 步自我檢驗照用，數字不變）：
   - 釘住那段，接觸點每格滑動 ≤ 3 mm。
   - 鞋底陷進地板 ≤ 2 mm。
   - 每次跨步每隻腳只抬一次。
   - 兩腳同時離地 0 格（跑跳除外）。

### 對身體端、服裝端的影響

- **身體端**：沒有影響。只要腳底那些點站直時貼地（身體端已確認腳跟、前腳掌貼地，足弓高 4 mm）。
- **服裝端**：鞋底如果有厚度，鞋底點要改從鞋子網格抓。目前從身體網格抓，鞋子再往下厚 N mm，整個人就會陷進地板 N mm。建議鞋子在 `outfit.json` 寫上鞋底厚度，動畫端照這個值把人抬高。

## 5. 長髮被上臂頂出來

### 狀況

- 長髮是一整片固定在頭骨上的網格，沒有修改器、沒有頭髮骨頭，只對 T 字姿勢調過。
- 手臂放下時，上臂整段在頭髮裡面，從背面靠肩膀的地方露出膚色。
- 頭端試過把頭髮整片往後退 7 cm，結果頭髮背面翻過來、腋下變亂，沒有採用。

### 五種做法比較

| 做法 | 成本 | 穩定性 | 適不適合我們（離線渲染短片） | 哪一端做 |
| --- | --- | --- | --- | --- |
| (a) 頭髮加骨頭，用程式擺 | 中 | 高、結果可預測 | 可以，但「避開手臂」要自己寫 | 頭端加骨頭；動畫端每鏡擺 |
| (b) 物理模擬（布料模擬、彈簧骨、Wiggle Bones 外掛） | 中～高 | 中：每鏡要先算好存起來，可能抖 | 頭髮會甩動、好看。Wiggle Bones 支援 Blender 5.0、可以撞指定網格、能一鍵存成關鍵影格。布料模擬的碰撞距離調大，頭髮會看起來浮在身上 | 頭端加骨頭；動畫端每鏡模擬 |
| **(c) 修正形態鍵＋上臂角度驅動** | **低～中（做一次）** | **很高、每次都一樣** | **最適合**：問題只出在「手放下」這個固定姿勢 | **頭端做一次**；動畫端只量、必要時調強度 |
| (d) 讓頭髮自動貼著身體外面（Shrinkwrap 等修改器） | 低 | 中：官方手冊自己說這只是「很粗糙的碰撞」，轉角超過 90° 會亂 | 只能當補丁 | 動畫端 |
| (e) 每鏡手動雕一個形態鍵 | 高（每鏡都要人工） | 高 | 只拿來救最後一兩鏡 | 動畫端 |

- **(c) 是什麼**：
  - 形態鍵（shape key）就是頭髮網格預先存好的一個變形版本。
  - 做法：把手臂放到「手放下」→ 雕出頭髮往後讓開的樣子 → 用驅動器（driver）把這個版本的強度接到上臂旋轉角。手臂從 T 字（強度 0）放下到貼身（強度 1），頭髮就跟著讓開。
  - 因為只有背面靠肩那一塊要讓開，不必整片後退 7 cm，所以不會翻面。
  - Blender Studio 的 Pose Shape Keys 外掛就是做這件事，改權重之後也不用重雕。
- **來源**：
  - https://studio.blender.org/tools/addons/pose_shape_keys
  - https://static.makehumancommunity.org/oldsite/documentation/corrective_shape_keys.html
  - https://extensions.blender.org/add-ons/wiggle-bones/
  - https://docs.blender.org/manual/en/latest/physics/cloth/settings/collisions.html
  - https://docs.blender.org/manual/en/latest/modeling/modifiers/deform/shrinkwrap.html
  - https://wiki.virtualcast.jp/wiki/en/vrm/setting/spring

### 建議

1. **主力用 (c)**：
   - 左右各一個形態鍵：`Hair_ArmDown_L`、`Hair_ArmDown_R`。
   - 驅動器讀 `J_Bip_*_UpperArm` 往下放的角度：0～75° 對應強度 0～1。
   - 驅動器在離線渲染完全可靠。我們的動畫是先算好每格姿勢、再存成關鍵影格，也可以不用驅動器，直接每格把強度寫成關鍵影格。
2. **要甩頭髮的鏡頭再加 (b)**：用 Wiggle Bones，碰撞體綁在上臂，模擬完存成關鍵影格。前提是頭端要先給頭髮加骨頭。開場片 B 目前沒有這種需求。
3. **(e) 只用來救個別鏡頭。**

### 哪一端做（建議，使用者還沒決定）

- **形態鍵本身建議頭端做**，在頭身接好的時候做一次：
  - 頭髮網格是頭端的，頭端也有「試接一副身體來調長髮」的自動流程，雕的時候需要身體在旁邊。
  - 動畫端每鏡重做，等於 (e)，成本高很多。
- **動畫端負責**：
  - 每鏡量有沒有露出來。新增 `hair_check`，照 `gown_check` 的做法：上臂皮膚的點，有沒有在頭髮外面、而且從鏡頭看得到。
  - 有露出來就把那一鏡的強度調高，或加一點強度。
- **使用者決定交給動畫端全包的話**，也做得到：
  - 動畫端在 `zanim_dress`（穿衣服那一步）幫頭髮加形態鍵，每鏡套用。
  - 缺點：頭換版時，形態鍵要跟著重做。

### 怎麼驗證

| 檢查 | 標準 |
| --- | --- |
| `hair_check`：手臂放下的每一格，上臂皮膚在頭髮外面、從鏡頭看得到的點 | 0 個 |
| 頭髮背面翻面的面數（和不加形態鍵比） | 不增加 |
| 近照：背面、斜後方、側面，手臂 0／45／75° | 目視：頭髮沒有凹進去或折起來 |

### 對身體端、服裝端的影響

- **身體端**：沒有影響。如果之後改了手臂粗細或肩寬，形態鍵的強度要重新量。
- **服裝端**：新娘的禮服有肩帶或袖子時，頭髮要同時讓開衣服。所以量的時候，上臂點要改成「上臂皮膚＋衣服最外層」。

## 6. 動作能不能不套 Mixamo、自己做？

> **使用者決定（2026-10-14）：繼續以 Mixamo 當底，只把局部改成要的動作。不做影片抽動作的實驗。**
> 評估過這台的顯示卡（RTX 2080 SUPER 8 GB）：夠，但要先關掉其他程式；每段 4 秒約 1～3 分鐘；第一次安裝約半天，而且官方不支援 Windows。

### 先講結論

- **最划算的是第 5 類「Mixamo 當底、只改局部」**，也就是我們現在的做法：
  - 身體的節奏和重心轉移是真人動作捕捉來的，看起來自然。
  - 劇情需要的手、接觸點、視線，再用程式和 IK 加上去。
- **Mixamo 找不到的劇情動作**（例：拉手腕、咬蛋糕的手），可以加第 2 類當補充：用手機拍真人示範 → 抽成骨架動作 → **只取手臂那一段**疊在 Mixamo 的底上。要不要加，先做 1 天的小實驗再決定。
- **文字生成動作、其他免費動作庫幫助不大**：
  - 兩者幾乎都沒有手指。
  - 兩者都不懂兩個人之間的互動。
  - 我們最缺的正好是這兩樣。

### 五類比較

| 做法 | 成品品質 | 花多少工 | 工具或模型 | 授權（公開、非商業的婚禮影片） |
| --- | --- | --- | --- | --- |
| 1. 程式手打關鍵影格 | 上限最高，但全看手藝。走路、轉身照步態週期做得出來；拉手腕、咬蛋糕這種表演，容易做得像機器人 | **最多**：一段 3 秒的表演動作，約半天到一天以上 | Blender Python（關鍵影格、曲線、IK），本機就能跑、不用 GPU | 全部自有，沒有問題 |
| 2. 從影片抽動作 | 身體大致可用。**手指和腳接觸是弱點**：手是平的、腳會滑；兩人互動時手對不準，常差數公分 | 中：架環境 1 次，之後每段約 1 小時，加上重套和修正 | 首選 GVHMR（本機、要 NVIDIA 顯卡）；手指另跑 HaMeR。MediaPipe 只輸出 33 個點、不是骨架，還要自己解。商用的有 Rokoko Video、Move.ai、DeepMotion | GVHMR 限非營利。SMPL 人體格式要到 MPI 註冊，條款允許「非商業藝術用途」。公開影片算不算，條文沒寫，要保險就寫信問 |
| 3. 文字生成動作 | 走、跳、揮手還可以；具體劇情互動基本做不出來。**沒有手指**，每段最長約 10 秒，腳會滑 | 中：架環境，加上每段重套 | MoMask、MDM、T2M-GPT（本機 GPU，約 6～8 GB）；商用 DeepMotion SayMotion（官方寫目前只有全身，沒有手和臉） | 程式多半是 MIT 授權。訓練資料來自 AMASS，限非商業的研究、教育、藝術用途，算勉強可以 |
| 4. 其他免費動作庫 | Bandai Namco 是專業動捕，約 3,000 段，有不同情緒的走路。CMU 老、雜訊多。**都沒有手指、沒有雙人動作** | 中：每個動作庫要寫一份骨頭對照、調方向（CMU 就是卡在手和膝蓋方向） | BVH 檔，本機 | Bandai Namco 是 CC BY-NC 4.0，**可以用但要標註出處**。CMU 所有用途免費。LAFAN1 禁止衍生作品，**避開**。ActorCore、Rokoko、Truebones 的免費包要逐一看條款 |
| 5. Mixamo 當底、只改局部 | 穩定、自然。風險是兩人接觸一定要靠 IK 修；整段大動作疊 IK 會更差，要「底保持安靜、只動做事的那隻手」 | 中，**程式大多已經有了** | 現有的 `mixamo_retarget`、`zanim_*` | Adobe 官方：可用於個人、商用、非營利作品，包括影片，不用標註；只禁止轉散布原始檔 |

### 怎麼接進三關審看（骨骼 → 正式版骨骼 → 低畫質預覽）

- 換動作來源**只影響第 1 關的輸入**。後面兩關、自我檢驗（第 7.5 步）、確認頁都不用改。
- 每類要加的東西：

| 做法 | 第 1 關（骨骼）要加的 | 第 2 關以後 |
| --- | --- | --- |
| 1. 手打 | 寫姿勢和時間曲線的工具。骨骼播放器照用 | 不變 |
| 2. 影片抽動作 | 一支「SMPL 轉我們骨架」的重套程式：先對齊兩邊站直時的姿勢，再對齊每根骨頭的軸向。這兩步沒做好，就會重演 CMU「手和膝蓋方向錯」。審看頁加一欄放原始影片對照 | 不變；腳滑照用鎖腳修 |
| 3. 文字生成 | 同 2（輸出也是 SMPL） | 不變 |
| 4. 其他動作庫 | 每個動作庫一份骨頭對照表＋方向修正 | 不變 |

### 要身體端提供什麼

| 項目 | 哪幾類需要 | 為什麼 |
| --- | --- | --- |
| 前臂扭轉骨（或在權重上把手腕扭轉分散到前臂） | 1、2、3 | 手腕轉大角度時，前臂會像糖果紙一樣扭成一條。Mixamo 也一樣，但目前還沒碰到大角度 |

- **服裝端**：沒有影響。衣服跟著骨頭走，動作從哪裡來都一樣。

### 建議先做的小實驗（1 天）

- **用哪一鏡**：B2 新娘拉新郎手腕那一段，比較兩個版本：
  - **A 版**：Mixamo 最接近的動作＋手臂 IK，也就是現在定案的版本。
  - **B 版**：手機拍真人示範約 4 秒 → GVHMR → 重套到我們的骨架 → 只取右手臂那一層，疊在同一個 Mixamo 底上。
- **時間分配**：
  - 上午：架 GVHMR（含 SMPL 註冊下載），跑完那支影片。
  - 下午：重套，兩個版本各渲一段固定機位的小片段。
- **比什麼**：
  - 現有程式量：腳滑幾公分、手腕和手的距離誤差、手肘和膝蓋方向有沒有翻錯。
  - 兩版並排放在確認頁，讓使用者看了決定。
- **判斷標準**：B 版方向沒有錯、而且使用者覺得比較自然，才把「影片抽動作」加進產線。否則照舊只用 Mixamo。
- **⚠️ 開始前要使用者同意的事**：
  - 下載 GVHMR、SMPL 等模型（規則：下載前先問）。
  - 這台電腦有沒有夠用的 NVIDIA 顯卡，還沒確認。

## 換版時的工作順序（建議）

1. 身體端出廠新身體，`RELEASE.json` 寫明骨架有變動。服裝端重做鞋子、褲腳、禮服。
2. 頭端在頭身接好時，做好頭髮的修正形態鍵（等使用者決定由哪一端做）。
3. 動畫端：
   1. 先改 `foot_lock`：釘住踩地的點、門檻照腳長換算。
   2. 補三項量測：膝蓋著地、兩腿互相穿插、`hair_check`。
   3. 寫 `retarget_diff.py`。
4. 每鏡依序跑：重套 → `retarget_diff` 對照 → `gown_check` 和 `hair_check` → 第 7.5 步小片段自己看 → 確認頁。
5. 新手勢（OK、合十）可以先做，和換版無關。身體端用試做身體驗證。
